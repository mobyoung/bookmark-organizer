# 书签整理方法论（Pipeline）

本文记录整理流水线的判定规则与原则，供 AI agent 在分类、打标签、失效判定时遵循，也方便复用与审计。

---

## 1. 去重规则（归一化 URL 精确匹配）

重复 = 两个书签指向"同一个网址"。但 URL 写法常有差异，需先归一化再比较：

- 小写 `scheme` 与 `host`
- 去掉 `user:pass@`（若有）
- 去掉默认端口（`http:80` / `https:443`）
- 去掉锚点 `#fragment`
- 去掉路径末尾多余斜杠（`/foo/` → `/foo`，但 `/` 保留）
- 反转义 HTML 实体（`&amp;` → `&`）
- **保留** query 参数（同路径不同参数视为不同页）

归一化后相同的，判为重复，每组保留一份（默认留首个出现）。脚本见 `scripts/analyze_bookmarks.py` 的 `normalize_url`。

---

## 2. 失效检测（6 级校验，仅生成候选）

> 原则：**云端探测不可靠，用户本地视图为权威**。所有"失效"都只是候选，删除前必须由用户在本地浏览器确认。

探测变体构建（对每个公网 URL）：
1. **协议回退**：`https` 不可达试 `http`，反之亦然。
2. **主页回退**：深层链接 404/410 → 回退到站点主页（`scheme://host`）再试。
3. **www 变体**：自动互试 `example.com` ↔ `www.example.com`。
4. **子域→主域**：子域不可达时，测其注册主域名是否可访问（区分"子域失效/主域存活"）。
5. **DNS 交叉**：两种协议均失败 → DNS 二次核验（解析不了 = 域名注销）。
6. **域名变更**：对确认失效站点，用网站名搜索 + 抓取，确认是否换域名（应改 URL 而非删）。

**跳过（永不判失效）**：局域网/内网（`192.168.` `10.` `127.` `*.local` `169.254.` `100.` 等）、浏览器内部协议（`chrome://` `file://` `about:` 等）、NAS / 云服务器（用户本地可访问）、被墙站点（云端不可达但用户可访问）。这些标"需本地确认"。

输出：疑似失效候选清单 + 子域失效 + 域名变更建议。用户复核后，agent 把结论写入 `decisions.json`（见 `clean_bookmarks.py`）。

## 3. 分类原则

- **按主题/用途分**，不按字母、时间、来源、访问频度。
- 以用户的**身份主线**划顶层（如设计师 / 开发者 / AI 爱好者 / 摄影），让常用入口聚焦。
- **合并同名中英文夹**：`摄影`+`Photography`、`电影`+`movie` → 统一一个。
- **拆分大杂烩**：如"资源"(300+) 按内容拆成 `设计资源`/`学习资料`/`软件工具`/`影音资源`。
- **本地/企业收藏夹独立**：NAS、服务器、公司内网（打印机/路由器/知识库）性质不同，不并入公共分类。
- **保留用户既有结构**：子文件夹层级尽量不动，只做必要的归并；用户原有的 `AI工具箱-` 等前缀体系予以保留。
- **用户已有中括号前缀原样保留**，不与新标签冲突。

---

## 4. 打标签（中括号前缀体系）

在"文件夹分类"之外，用 `【类型】`前缀在**同分类内**标注内容性质，好处是跨文件夹也能按类型检索。

- 全角 `【】` 为体系符号；用户原有的半角 `[ ]` 前缀视为有效，原样保留。
- 标签由 **AI 基于书签内容设计**，贴合该用户实际，不套模板。
- 典型映射层次（`assets/default_bookmark_taxonomy.json` 可改）：
  - `folder_map`：顶层文件夹 → 默认标签（如 `設計综合` → `【设计】`）
  - `subfolder_map`：子文件夹 → 更细标签（如 `設計综合/建筑设计` → `【建筑】`）
  - `keyword_refine`：按关键词细化（如文件夹"设计资源"内含"字体"→`【字体】`）
  - `default_tag`：兜底 `【其他】`；`root_tag`：根级书签（书签栏）`【快捷】`
- 优先级：用户已有前缀 > subfolder > folder > keyword > 兜底。
- 应用后检查 `【其他】`/`【快捷】` 样本，回头补 `keyword_refine` 再跑，直到覆盖率满意。

---

## 5. 交付与导入

两种交付方式（详见 `SKILL.md` S5 与 `chrome_import.md`）：

- **A. HTML 自导入**：最透明。Chrome 导入时可能生成「已导入」文件夹，需手动拖一次（带 `PERSONAL_TOOLBAR_FOLDER`）或全进书签栏（不带）。无"已导入 + 精确布局"兼得。
- **B. 直写 Chrome Bookmarks**：精确布局（书签栏 N + 其他书签 M + 无已导入），但需完全退出 Chrome、关同步、多 profile 须指定目标。脚本自动备份、校验退出状态。

---

## 6. 透明度与可回退

- 任何阶段不覆盖用户原始导出；产物均为新文件名。
- `clean_bookmarks.py` 生成《书签改动清单.md》，逐条记录删除/合并/移动及依据。
- 方式 B 写入前自动备份 `Bookmarks` 到 `chrome_bookmarks_backups/`。
- 用户随时可用原始导出重来。
